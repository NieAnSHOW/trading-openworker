Cool-Admin 会员登录授权流程

方案 B · 浏览器授权闭环：桌面客户端唤起系统浏览器 → 独立授权页登录 → JWT form-POST 回落本机 → sidecar 拉取 Vault 密封凭据并注入内置 trading-server 供应商。 密钥明文永不过网络、token 不进浏览器历史。

coworker/coolauth.py POST /auth/cool/callback POST /app/ai/member/credentials midway 服务端零改动

参与方

🖥 OpenWorker GUI
React + Tauri。登录按钮 → cloudLogin()，五处入口共享；模型下拉消费注入结果。
⚙ Sidecar（本机 127.0.0.1:PORT）
FastAPI + 引擎同进程。持有 state 表、SecretStore、Trading Server 注入与模型同步。
🌐 系统浏览器 · 授权页
cool-admin-vue 独立模块 /auth（免 admin token 守卫）。密码 / 短信双 tab。
🗄 cool-admin-midway（API）
app 域 JWT 签发 + Vault Transit 密封会员网关密钥。全程零改动。

时序流程

8 步闭环。①–③ 发起与登录，④–⑤ 回落与会话落盘，⑥–⑦ 凭据拉取与注入，⑧ 收尾。

1
用户点击「登录」 → sidecar 生成一次性 state
GUI POST /v1/cloud/login（复用 stock cloud 路由，按 cool_admin_base_url 多态分支）。sidecar 生成 16 字节 hex state，存入进程内一次性表 coolauth._pending_logins（TTL 600s，防任意网页灌 token）。
POST /v1/cloud/login
2
sidecar 唤起系统浏览器打开授权页
{cool_admin_base_url}/auth?port={COWORKER_PORT}&state={hex16}
前端地址（dev: http://localhost:9000）。Tauri 与纯浏览器 dev 行为一致（sidecar 自己 webbrowser.open）。
webbrowser.open
3
授权页登录（app 域，不碰 admin 会话）
手机号+密码 / 短信验证码（图形验证码 → /app/user/login/smsCode 发码）。登录提交走 /app/user/login/password 与 /app/user/login/phone（验证码登录），统一 service.request baseUrl（dev 经 vite proxy）。登录成功 不写 storage、不调 user.setToken —— admin 控制台会话零污染。
POST /app/user/login/*
4
form-POST 回落本机（导航式提交，无 CORS / 不进历史）
POST http://127.0.0.1:{port}/auth/cool/callback
  state        —— 必须命中一次性表，否则 400
  token        —— app 域 JWT（access）
  refreshToken / expire / refreshExpire
  account      —— 手机号（展示用）
/auth/cool/callback tokenless 白名单
5
sidecar 校验 state → 会话落盘 → 「登录成功」落点页
state 一次性消费；JWT 对存入 SecretStore profile cool:auth（0600）。浏览器立即收到中文落点页（不等凭据拉取）。
cool:auth
6
后台任务拉取密封凭据（每次临时 X25519 密钥对）
POST {cool_admin_api_url}/app/ai/member/credentials
  Authorization: Bearer <token>
  { "clientPublicKey": "<X25519 DER-SPKI base64>" }
→ { code:1000, data:{ version:2, baseURL, models[], apiKeySeal{…} } }
私钥仅存 sidecar 内存；API 地址独立于前端地址（dev: 127.0.0.1:8001，空则回退同域）。
credentials
7
本地解封 → 注入 Trading Server → 模型列表权威同步
解封：ECDH(serverEph, clientPub) → HKDF-SHA256(salt32, info="vibe-trading/member-credential/v1") → AES-256-GCM（镜像 midway userMember.ts 密封算法）。 注入：set_provider("trading-server", {api_key, base_url}) + 模型 add + prune（服务端列表为权威，撤销即移出选择器）。
trading-server
8
GUI 状态翻转 · 登录完成
登录入口轮询 /v1/cloud/status 翻转 → 广播 CLOUD_CHANGED；Settings ▸ 模型「Trading Server」卡片点亮，对话框下拉可选 trading-server:<model>。
✓ 闭环

模型列表同步触发点（服务端列表为权威 · add + prune）

时机 链路 语义
登录回落 回调路由后台 task → sync_credentials 首次注入（不阻塞落点页；失败保留登录态）
sidecar 启动 lifespan：已登录即后台补同步 事故守卫 —— 曾失败一次的注入下次启动自动恢复
模型下拉打开 cloudSync() → loadSettings（fire-and-forget） 选择器即开即新；失败保留缓存列表
Settings ▸ 模型 打开 ModelsTab mount：缓存秒显 → sync → 二次刷新 管理视图自己管自己的新鲜度，无跨组件事件
显式接口 POST /v1/cloud/sync 幂等，任意客户端可调
配置（~/.config/coworker/config.toml）
# 前端：授权页（浏览器打开）
cool_admin_base_url = "http://localhost:9000"
# 服务端 API：refresh + 凭据（空 = 与前端同域）
cool_admin_api_url  = "http://127.0.0.1:8001"
生产同域形态只需 cool_admin_base_url（nginx 将 /app/* 反代至 midway）。配置即开关：两键皆空 ⇒ 回落 stock OpenWorker cloud 登录。
安全属性
  • • state 一次性 nonce：非本 sidecar 发起的回调 400，防任意网页灌 token
  • • form-POST 回落：导航式提交无 CORS preflight，token 不进浏览器历史
  • • 密钥明文不过网络：Vault 密封 + X25519 信封，仅 sidecar 本地解封
  • • app / admin JWT 隔离：授权页自持 app 域 token，不覆盖 admin 会话
  • • key 只落 0600 SecretStore，不进日志 / 提示词 / API 响应
  • • 半配置拒绝：Trading Server 缺端点或 key 直接 raise，绝不回落 api.openai.com
